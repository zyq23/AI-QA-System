# RAG 问答系统质量提升计划

## 诊断结论（系统不足全景）

经过对代码、协作文档、数据库与运行环境的全面审计，当前系统的不足分为六类：

### A. 泛化能力缺失（最核心问题）
- `app/services/retrieval.py` 与 `app/services/llm.py` 中存在 **~85 处硬编码领域规则**：约 40 个查询扩展块（retrieval.py:493-632）、约 25 个 rerank 定向加分块（retrieval.py:920-1076）、~20 个 grounding 特判（retrieval.py:719-807）、预置答案（llm.py:1430-1466，如"四个支柱"无条件返回固定答案）。
- 这些规则与 27 题评测集**一一对应**，当前 27/27 的成绩大量依赖"背题"。新问题、新文档域将完全失去这些支撑。docs 中 R-03 风险（规则复杂度无限增长）已被明确标记为长期隐患。

### B. 索引与数据卫生（三处计数互不相等）
- SQLite 当前版本 chunks=3,789，总 chunks=10,839（7,050 个过期版本残留），Chroma 向量=7,485——三者失配，检索范围被 stale chunks 污染。
- jobs 表 2 个永久 running（5/25、5/28 起）+ 6 个永久 queued，无超时回收。
- DB 从未 VACUUM（77.9MB）；Chroma 有 32MB 孤儿向量段和空 test collection；uploads 751MB 全版本保留。
- 决策 D-030/D-031 的 27/27 成绩实际是在这个失配索引上测得的，重建后必须复验。

### C. 检索与答案能力短板
- 中文 FTS5 用 unicode61 分词（逐字切分），无中文分词器；BGE-M3 未加 query instruction；rerank 降级到词法打分时无告警。
- **摘要/总结类问题 0 道可答**（9 道 blocked 中 2 道是 grounding_insufficient 的摘要题）——系统只会"抽取式事实题"。
- 幻觉防线过度：`_contains_source_leak` 把"文件"这种常见词当泄漏词，好答案被误杀；`_anonymize_source_names` 可能破坏正常回答。
- 查询改写依赖 LLM（qwen），失败时启发式改写很弱；FTS 查询拼接未转义引号可致 500。

### D. 解析与 OCR 残留问题
- slide-27 WMF 加载失败（唯一未解决的解析告警）；slide-74/89 等弱语义 OCR 噪声块仍在索引中；DOCX 内嵌图片完全无 OCR；`ocr_utils.py:7-29` 硬编码"宇树 G1/华为/Jupyter"等锚点词加分（且与知识库实际内容"轩辕网络"不匹配）。
- PDF 每页所有嵌入图片无条件 OCR（两次引擎都跑），延迟极高。

### E. 安全与工程卫生
- `config.py:12` 读取**外项目** `../qianliyan/.env`；`.env` 中有活 DashScope/RAGFlow key（历史重写后未轮换）；admin token 走 URL query 参数；`/api/chat/query`、`/api/robot/query` 无鉴权无限流；conversation_id 无属主校验（可跨用户读写）。
- 每请求新建 SQLite 连接（无 busy_timeout，有 "database is locked" 风险）、每请求新建 httpx Client/ThreadPoolExecutor；Spark 每次调用 `asyncio.run`。
- 无 CI；`reindex_all.py` 在 import 时就执行且无备份；默认评测数据集路径指向不存在的文件；README 与 .env.example 漂移；AGENTS.md 统计数字过期（实际 7 文档/19 版本/10839 chunks）。

### F. 评测体系局限
- 27 题与硬编码规则一一对应，无法度量真实泛化能力；摘要类没有正向样例；无 CI 自动回归；EvaluationService 不原生支持 must_block 语义。

## 实施计划（四个阶段，每阶段结束跑回归）

**总原则**：遵守 AGENTS.md（先补评测入口再做行为改动；每步 Git 提交；handoff/decisions 文档同步更新）。按用户未答复的默认判断：采取渐进式替换 + 全范围覆盖（检索答案质量优先），扩充评测集，允许离线索引重建（先备份）。

### 阶段 0：安全网与基线（先行）
1. 建 git 分支 `quality-upgrade`；修正 AGENTS.md 统计数字。
2. **扩充评测集**到 ~80 题：基于 7 份文档新增泛化题——规则未覆盖的新 factoid、跨文档对比题、摘要归纳题、负面题（知识库中没有的）、同义改写题。这是验证去规则化后"真实能力"的唯一手段。
3. 固化回归入口：脚本化 `run_eval.py`（修掉指向不存在数据集的默认值），跑一次现有 27 题 + 新题的**改造前基线**，留存结果。

### 阶段 1：索引与数据卫生重建
1. 备份 `data/runtime/app.db` 与 `data/chroma`。
2. 编写带 dry-run 的清理脚本：删除 12 个过期版本对应的 7,050 stale chunks、清 stuck jobs（标 failed）、VACUUM、清 Chroma 孤儿向量段与 `chunks_test`、重建 `chunks` collection 使三处计数一致。
3. 更新 `reindex_all.py`：加 main() 守卫、dry-run、备份参数；用它对 7 份文档**全量重解析重建**（含 OCR）。
4. 解析侧小修（不改架构）：slide-27 WMF 降级处理、DOCX 图片 OCR 接入、`ocr_utils.py` 硬编码锚点词移到配置或删除、PDF 图片 OCR 改为仅在文本稀疏页触发。
5. 复跑 27 题回归，确认索引重建未破坏成绩。

### 阶段 2：检索层去硬编码 + 泛化能力
1. **中文分词修复**：FTS5 换 jieba 预分词写入 search_text（或 fts5 tokenize 改造），query 侧同步分词；解决逐字切分导致的召回噪声。
2. 逐类替换硬编码规则为通用机制：
   - 查询扩展块 → 通用同义词表（数据文件化，可维护）+ LLM/embedding 近邻扩展；
   - rerank 定向加分块 → 通用信号（章节匹配、页码邻近、OCR 置信度、文档新近度、sibling 聚合）+ 通用去噪；
   - grounding 特判 → 通用证据覆盖度判定（焦点词命中率、同页聚合、枚举完整性）；
   - **预置答案（canned answers）全部删除**，由"证据驱动 + 快路径抽取"替代。
3. 每替换一类跑一次回归（27 题 + 新 80 题），保留原规则文件在 git 历史中可回滚。
4. 修复：FTS 引号转义、reranker 降级告警、`_contains_source_leak` 改为只匹配"文件名+扩展名"模式、`_anonymize_source_names` 收紧。

### 阶段 3：答案层泛化 + 摘要类问题支持
1. 摘要类问题：新增"多 chunk 聚合生成"路径——当判定为 summary 类型时，召回该主题下多页 chunks（页组聚合），prompt 支持结构化摘要输出，grounding 判定从"单 chunk 强匹配"改为"多点证据覆盖"。
2. 生成与审核 prompt 重构：减少模板特判，统一走"证据→答案"链路；qwen 改写失败时的启发式改写加强（同义词表驱动）。
3. 幻觉防线精细化：从"关键词黑名单"改为"支持句覆盖率 + 数字/专名一致性校验"。
4. 跑完整回归 + 新评测集，目标：27 题维持 27/27，新泛化集达到可接受的基线并记录。

### 阶段 4：工程卫生与稳定性
1. 连接与性能：SQLite 连接池/busy_timeout/WAL checkpoint 策略；httpx Client 复用；ThreadPoolExecutor 全局化；Spark `asyncio.run` 改为可复用事件循环；rerank CPU 批量优化。
2. 安全（不动功能）：移除 `../qianliyan/.env` 依赖；`.env.example` 补齐缺失 key 并标注需轮换 live key；admin token 改 header 传递；conversation 属主校验；chat/robot 接口加简单限流。
3. 韧性：job 超时回收器；ingestion 失败重试；Chroma 维度失配时禁止静默 reset。
4. CI：GitHub Actions 跑 pytest（stub 模式）；README 与实际对齐；handoff/decisions 文档按 AGENTS.md 契约更新。

## 验收标准
- 每阶段 Git 提交 + `docs/codex-handoff.md` 更新；行为变化均附评测证据。
- 最终：现有 27 题回归不回退（≥27/27）；新泛化集有基线数字且较基线提升；索引三处计数一致；stuck jobs 清零；安全项 E 全部整改。
- 明确限制：RAGFlow 侧因 ragflow/ 目录已删除，只做现象记录不做能力结论（遵守 D-008）。
